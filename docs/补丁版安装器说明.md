# 补丁版 XposedInstaller 与官方原版的差异说明

> 本文面向社区分享场景：说明本仓库 Releases 分发的 `XposedInstaller_v4_signed.apk`
> 相对 rovo89 官方原版改了什么、为什么改、如何验证，以及配套用法。
> 补丁脚本：`tools/patch_installer_v4.py`；基料：官方 3.1.5 未签名原包
> （`XposedInstaller_orig_clean.apk`，Releases 提供，也可自行从 APKMirror 等存档获取）。

## 基线

- 官方源码：https://github.com/rovo89/XposedInstaller （commit `8f8f2d7`，"Bump version to 3.1.5"，versionCode 43）

## 改动内容：有且仅有一处

**DEX 字符串池中的框架状态检测路径替换**：

```
/su/xposed/xposed.prop   (22 字符)  →  /storage/emulated/0/xx   (22 字符)
```

- 安装器用它判断"Xposed 框架是否已安装"。官方版只认 `/su/xposed/xposed.prop`
  （SuperSU 时代安装方式）、`/system/xposed.prop`（recovery 直写安装方式）等路径；
  这两条路径在 Magisk systemless 方案下都不存在——topjohnwu 打包的框架模块把
  `xposed.prop` 放在模块根目录（`/data/adb/modules/xposed/xposed.prop`），每次开机
  由 `post-fs-data.sh` 复制到 `/sbin/xposed.prop`，官方安装器不检查这个位置。
- 因此官方安装器 + Magisk 框架模块的组合，**状态页永远显示"框架未安装"**
  （功能不受影响，纯显示问题）。补丁版把检测路径改到 `/sdcard/xx`，
  只需把 prop 内容推到该位置即可正确显示框架版本/架构。

## 补丁的技术约束（为什么改这一个字符串都这么费劲）

DEX 格式三铁律，全部踩过（过程详见 `阶段1侦察成果.md` §5.3）：

1. 字符串区禁止留空洞——新旧串必须**等长**（22 字符），uleb128 长度前缀不变
2. 文件大小恒等——逐字节等长替换，模式串须含结尾 `\x00`
3. 字符串池必须保持字典序——`/storage/emulated/0/xx` 恰好落在邻居
   `/storage/emulated` 与 `/sys/module/dm_verity` 之间（脚本内置断言验证）

替换后重算 DEX 的 sha1 与 adler32 校验，剥离旧签名后用独立 keystore 重签
（jarsigner，与仓库其他制品同源）。

## 功能对比

| 功能 | 官方原版 3.1.5 | 补丁版 v4 |
|---|---|---|
| 模块启用/禁用（写 modules.list） | 相同 | 相同 |
| Xposed 日志查看 | 相同 | 相同 |
| 框架状态显示（Magisk systemless 下） | 永远"未安装" | 读 `/sdcard/xx`，正确显示 |
| 在线下载框架 | 已失效（dl-xda/xposed.info 于 2021 年关站） | 同样失效（框架请用 Magisk 模块 zip 刷入） |
| 其余一切 | — | 无任何其他改动 |

## 配套用法（装完补丁版执行一次）

```bash
adb shell pm grant de.robv.android.xposed.installer android.permission.READ_EXTERNAL_STORAGE
adb push xx.prop /sdcard/xx     # 内容：version=89 / arch=arm64 / minsdk=25 / maxsdk=25
```

也可从已刷框架的设备直接取：`adb shell "su -c 'cp /sbin/xposed.prop /sdcard/xx'"`。

## 安全性说明

- 改动为单字符串等长替换，可用 `tools/patch_installer_v4.py` 对
  `XposedInstaller_orig_clean.apk` 复现（脚本含排序断言，无法复现会中止）
- 签名 keystore 为本项目自有（不入库），与官方签名不同，
  因此**不能覆盖安装官方签名的 XposedInstaller**，需先卸载再装
